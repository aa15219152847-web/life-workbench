Cloudflare 云同步部署手册

Lan工作台 · 给「云同步」和「兑换码核销」接上云端 · 预计用时 15~20 分钟 · 全部免费
开始前请确认：你有两个东西在手边——① 一个能收邮件的邮箱；② 电脑上能打开 dash.cloudflare.com（建议用 Chrome/Edge）。本手册全程不需要信用卡。

你要做的 6 件事（总览）

  1. 注册 Cloudflare 账号（约 3 分钟）
  2. 创建 Worker 并粘贴代码（约 5 分钟）
  3. 创建 KV 存储空间（约 2 分钟）
  4. 把 KV 绑定到 Worker（约 2 分钟，最关键一步）
  5. 部署 Worker 并测试（约 3 分钟）
  6. 把地址填进前端代码并推送上线（约 5 分钟）

第一步：注册 Cloudflare 账号

1打开注册页
浏览器打开：https://dash.cloudflare.com/sign-up
2填写注册信息
  • Email：填你的常用邮箱（建议 Gmail 或 QQ/163 邮箱均可）
  • Password：填一个密码（至少 8 位，建议字母+数字+符号）
  • 点 Sign Up（注册）按钮
3验证邮箱
去邮箱收信，找到 Cloudflare 发来的验证邮件，点邮件里的确认链接。没收到就检查垃圾箱，或等 1 分钟再点一次「重新发送」。
4跳过域名引导
登录后可能会问你要不要添加网站（Add a site）——直接跳过/不添加，我们不需要域名，你只用 Workers 服务。
如果看到 "Choose a plan" 之类的页面，选免费的 Free 计划即可（不要选 Pro 或 Enterprise）。
完成标志：进入 dash.cloudflare.com 首页，能看到你注册的邮箱和账号信息。

第二步：创建 Worker 并粘贴代码

1进入 Workers 页面
登录后，在左侧菜单栏找到 Workers & Pages（图标是一个方块拼图），点击进入。
如果没看到左侧菜单，点左上角 Cloudflare logo 回到首页，再找 Workers & Pages。
2创建一个 Worker
在 Workers & Pages 页面点蓝色按钮 Create application（创建应用）→ 再点 Create Worker（创建 Worker）。
3给 Worker 起名
在 Name 输入框里填：lan-workbench-sync
（名字可以随意，但建议用这个，后面好认）
点 Deploy（部署）→ 会跳转到 Worker 管理页。
4打开代码编辑器
在 Worker 管理页点 Edit code（编辑代码），会打开一个在线代码编辑器（左边是代码，右边是预览）。
5粘贴代码（重要！全部替换）
先全选删除编辑器里默认的示例代码（Ctrl+A 全选 → Delete），再把下面这段完整代码粘贴进去：
export default {
  async fetch(request, env, ctx) {
    const cors = {
      'Access-Control-Allow-Origin': '*',
      'Access-Control-Allow-Methods': 'POST, OPTIONS',
      'Access-Control-Allow-Headers': 'Content-Type',
    };
    if (request.method === 'OPTIONS') {
      return new Response(null, { status: 204, headers: cors });
    }
    if (request.method !== 'POST') {
      return new Response(JSON.stringify({ ok: false, error: 'method not allowed' }), { status: 405, headers: { ...cors, 'Content-Type': 'application/json' } });
    }
    try {
      const body = await request.json();
      if (body.action === 'put') {
        if (!body.body || typeof body.body !== 'string') {
          return new Response(JSON.stringify({ ok: false, error: 'empty body' }), { status: 400, headers: { ...cors, 'Content-Type': 'application/json' } });
        }
        const parsed = JSON.parse(body.body);
        const savedAt = parsed && parsed.savedAt ? parsed.savedAt : new Date().toISOString();
        await env.SYNC_KV.put('lan_sync', body.body, { metadata: { savedAt } });
        return new Response(JSON.stringify({ ok: true, savedAt }), { status: 200, headers: { ...cors, 'Content-Type': 'application/json' } });
      }
      if (body.action === 'get') {
        const val = await env.SYNC_KV.get('lan_sync');
        if (!val) {
          return new Response(JSON.stringify({ ok: false, error: 'no backup yet' }), { status: 404, headers: { ...cors, 'Content-Type': 'application/json' } });
        }
        return new Response(val, { status: 200, headers: { ...cors, 'Content-Type': 'application/json' } });
      }
      return new Response(JSON.stringify({ ok: false, error: 'unknown action' }), { status: 400, headers: { ...cors, 'Content-Type': 'application/json' } });
    } catch (e) {
      return new Response(JSON.stringify({ ok: false, error: e.message }), { status: 500, headers: { ...cors, 'Content-Type': 'application/json' } });
    }
  },
};
注意：这段代码里有一处不能改——env.SYNC_KV。第四步绑定的 KV 变量名必须和它完全一致，否则会报错。

第三步：创建 KV 存储空间

1回到 Workers & Pages 首页
点左侧菜单 Workers & Pages 回到列表页，然后点 KV 标签（在页面顶部，和 Workers 并列）。
新版界面里 KV 入口在：左侧菜单 Workers & Pages 下方，或页面顶部的 KV 选项卡。
2创建 KV 空间
点 Create a namespace（创建命名空间）→ 名称填：lan-sync-kv → 点 Add（添加）。
KV 是什么：就是一个云端"小柜子"，用来存你的加密备份数据。免费额度每天 10 万次读取、1000 次写入，个人项目完全够用。容量上限 1GB（实际单个 key 最大 25MB，你的加密备份一般只有几十~几百 KB，放心）。

第四步：把 KV 绑定到 Worker（最关键一步）

1进入 Worker 的设置
回到 Workers & Pages → 点你创建的 lan-workbench-sync → 点顶部 Settings（设置）标签页。
2找到 KV bindings
在 Settings 页往下滚动，左侧或页面里找到 Bindings（绑定）区域，里面有 KV namespace bindings，点 Add binding（添加绑定）。
3填写绑定（三处都要对）
字段填什么说明
Variable nameSYNC_KV必须全大写，必须叫 SYNC_KV，和代码一致
Namespacelan-sync-kv选第三步创建的那个
点 Save（保存）。
最容易错的一步：Variable name 填成小写 sync_kv 或别的名字，会导致部署后上传报错 "SYNC_KV is not defined"。填完先截图留底。

第五步：部署 Worker 并获取地址

1保存并部署代码
回到代码编辑器（Edit code），右上角点 Deploy（部署）按钮。等几秒，出现 "Success" 或 "已部署" 字样。
2复制 Worker 地址
在 Worker 管理页能看到一个 xxx.workers.dev 格式的地址（你的专属子域），例如：lan-workbench-sync.你的名字.workers.dev
点地址右边的复制图标，存到记事本里。这就是后面要填进前端的地址。

第六步：测试 Worker（可选但推荐）

1用浏览器直接测
新开一个浏览器标签页，地址栏输入你的 Worker 地址并回车。页面会显示 JSON：
{"ok":false,"error":"method not allowed"}
显示这个说明 Worker 正常运行（它只接受 POST 请求，浏览器访问是 GET，所以返回这个提示，属正常现象）。
2用命令行测写入/读取（推荐）
打开电脑的「命令提示符」或终端，运行下面两条命令（把地址换成你的）：
curl -X POST https://你的地址.workers.dev -H "Content-Type: application/json" -d "{\"action\":\"put\",\"body\":\"{\\\"savedAt\\\":\\\"2026-08-09T00:00:00Z\\\",\\\"hello\\\":\\\"world\\\"}\"}"
curl -X POST https://你的地址.workers.dev -H "Content-Type: application/json" -d "{\"action\":\"get\"}"
第一条应返回 {"ok":true,"savedAt":"..."}，第二条应返回你刚存的内容。两条都通，说明云端存储 OK。

第七步：把地址填进前端代码

1打开项目里的 index.html
用 VS Code（或任意文本编辑器）打开 life-workbench-git/index.html，按 Ctrl+F 搜索：CLOUD_SYNC_ENDPOINT，找到这一行：
const CLOUD_SYNC_ENDPOINT = ''; // TODO: 明天填入 Cloudflare Worker 地址（如 https://xxx.workers.dev/sync）
2把地址填进去
改成（注意：填的是你的 Worker 地址，不要带 /sync 后缀）：
const CLOUD_SYNC_ENDPOINT = 'https://lan-workbench-sync.你的名字.workers.dev';
保存文件。

第八步：提交推送，让线上生效

1提交并推送
在项目目录打开终端，执行：
git add index.html
git commit -m "feat: 启用云同步（Cloudflare Worker 已配置）"
git push origin main
推送后 Cloudflare Pages 会自动重新构建，大约 1~2 分钟后线上生效。

第九步：在工作台里验证（最终确认）

1打开线上工作台
访问你的工作台网址，进入「数据」页 → 找到「云同步」卡片（如果被折叠，先展开「数据管理」）。
2上传测试
输入一个同步码（至少 8 位，例如 mytest123）→ 点 加密上传。出现「云端同步完成」提示，就成功了。
3恢复测试（换设备模拟）
换一台设备（或开无痕窗口）打开工作台 → 数据页 → 输入同一个同步码 → 点 云端恢复，看到数据回来了就大功告成。

常见问题排查

现象原因 / 解决办法
「加密上传失败: SYNC_KV is not defined」第四步 KV 绑定没生效或变量名不对。回到 Worker → Settings → Bindings 检查变量名是否为大写 SYNC_KV，重新保存后再部署一次。
「云端待配置」提示一直出现前端 CLOUD_SYNC_ENDPOINT 还是空字符串。检查 index.html 是否填了地址并已 push 上线（线上可能有缓存，强刷 Ctrl+Shift+R）。
浏览器打开 Worker 地址显示 method not allowed正常现象，Worker 只接受 POST。用第六步的 curl 命令测试。
上传成功但恢复是旧数据KV 的 key 是固定的 lan_sync，所有用同一个同步码的用户共用一个备份槽位。这是单用户备份设计，多用户版本在兑换码管理后台方案里再做。
国内访问 worker 地址慢/超时workers.dev 子域在国内网络偶尔不稳定。可以后续给 Worker 绑定你自己的域名（需要已备案域名）或用代理，属可选优化。
提示同步码错误同步码用于本地派生 AES 密钥，恢复时用错码会解密失败，提示「同步码可能不正确」。换回原来的码即可。

免费额度一览（放心用）

资源免费额度你的用量
Workers 请求10 万次/天每天几十次，绰绰有余
KV 读取10 万次/天同上
KV 写入1000 次/天每次同步 1 次写入
KV 容量1GB加密备份几百 KB，几乎不占
隐私说明：云端只存 AES-GCM 加密后的密文，服务端无法查看内容。加密密钥由你的同步码在本机派生，云端没有任何密钥材料——同步码就是你的数据钥匙，务必自己保管好，忘了就恢复不了。
做完之后：云同步启用后，建议顺手把「数据页 → 数据管理」里的说明文案看一眼，确认同步提示不再是"云端服务待配置"。之后我们可以继续做兑换码管理后台（方案A），把核销和发码也接到这个 Worker 上。
